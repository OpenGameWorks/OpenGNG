# CodeWarrior idioms: Types and conversions

bool, signedness, masks and float/int conversions as CodeWarrior emits them. Each entry pairs an asm pattern seen in the original with the source that produces it, and names the function that proved it.

- A single `abs.s` comes from the MW intrinsic `__s_abs(f)` (no declaration needed); `fabsf` and a `f < 0 ? -f : f` ternary compile to a call or a branch.
- A masked low-half store kept as `ori $vN,$zero,0xFFFF` + `and` (instead of a plain `sh`) means the source also masked a shifted high half: `d[1] = x >> 16; d[2] = x & 0xFFFF; d[3] = (y >> 16) & 0xFFFF;`. The redundant mask after `>> 16` is dropped but leaves 0xFFFF materialized in a register. Try masking each `>> 16` store in turn (sound.c: 11 matches).
- `daddiu $r,$zero,1` (64-bit) for a flag constant is a `bool` local set to `true`; `int`/pointer/`long` flags give `addiu`. When the flag register also holds a pointer in one block, the source has a separate pointer local in that block that shares the register (`Player::AnimationViewer`: `bool bBuilt` + `PMNode *pShield`).
- An `mtc1 $zero,$fN` hoisted above unrelated stores and then used in a float compare is a `float fZero = 0.0f;` local shared by a float member store and the test: `float fZero = 0.0f; *(float *)&m_x = fZero; if (m_y[0] != fZero)` (`PlingEffect` ctor).
- A float zero test whose `c.eq.s` names the loaded value first (`c.eq.s $f1, $f0` with `$f0` the zero) is the bare truth test `if (f)` / `&& f`; `f != 0.0f` and `0.0f == f` both put the zero first (`FontNode::Render`, `PCDFile.cpp` neighbours).
- `mula.s`/`madd.s`/`msub.s` come from C: CodeWarrior fuses a sum of products written as one expression (`a.x * b.x + a.y * b.y + a.z * b.z`, Camera::Dot in `src/game/Camera.cpp`). A temporary or a separate statement per product breaks the chain into `mul.s` plus `add.s`.
- A constant 1 loaded with `daddiu reg,$zero,1` where an int would give `addiu`/`li` is a `bool` local: `bool f;`, `f = true;` / `f = false;`, `if (!f)`; `f == 0` adds an `andi 0xFF` (`ReadData` in `src/game/PCDFile.cpp`). `tools/permute.py FILE 0xADDR` tries this respelling among others.
- `dsll32 r,r,N` then `dsrl32 r,r,N` (or `dsll`/`dsrl` by N) on an int is a mask of its low 32-N bits written plainly: `x & 0xFFFFFF` for N = 8. CodeWarrior emits the shift pair instead of loading the constant; a hand-written 64-bit shift compiles to another amount (`DecodeTextureHandle` in `src/game/PTextureManager.cpp`).
- A function whose result the original tests with a bare `beqz v0` and whose locals set 1 with `daddiu` returns `bool`: `bool F(...)`, a `bool` result local, and callers written `if (F(...))`. `F(...) != 0` on a bool adds `andi 0xFF`, and an `int` return of a bool local adds it at the return (`BuildCollisionArray` in `src/game/PMeshNode.cpp`). `long` and `long long` locals still load 1 with `addiu`.
- An unsigned `sltu v0,$zero,x` then `xori 1` is `bool b = !(x > 0); if (!b)`; `x == 0` gives `xor`/`sltiu` (`Open` in `src/game/PDynamicBuffer.cpp`).
- A 128-bit constant built in a register (`lui; dsll32; pcpyld v0,v0,$zero; sq`) is a 64-bit constant cast to `u_long128`: `q = (u_long128)0x3F80000000000000ULL;`.
- `bltz v; srl; mtc1; cvt.s.w` then `andi 1; or; mtc1; cvt.s.w; add.s` is CodeWarrior's inline unsigned-to-float conversion: write `(float)v` with `v` unsigned. A hand-written `(v >> 1) | (v & 1)` branch picks other registers (`RequestCloserThanAttacking` in `src/game/EntityAttackManager.cpp`).
- The float-to-unsigned conversion (`c.le.s` against 2147483648.0f, `sub.s`, `cvt.w.s`, `or 0x80000000`) is compiler output too: write `(unsigned int)f` (`PSTAnim::Load`).
- A 64-bit colour packed from floats with `cvt.w.s; mfc1; andi 0xFF; dsll N; or` and no `dsll32`/`dsra32` pair is `((unsigned long long)(unsigned char)(int)f) << N` per channel (`PFlashScreen::Render`); `(int)f & 0xFF` sign-extends and adds the shift pair.
- Calls to `fptodp`, `_dpfgt`, `_dpfge` and other soft-double helpers are compiler output for `double` arithmetic: a float passed to `printf` is promoted by itself, and a 64-bit literal built in `a1` before `_dpfgt` is a double constant (`if (1.0f - dot > 1e-6)` in `MathAPI::QuatSlerp`). Explicit helper calls schedule the literal differently.
- `slti $at, x, N` then `bnez $at` is `x > N-1`; `x >= N` compiles to `slti` into an ordinary register (`TriggerSystem::ResetTrigger`). The unsigned form holds too: `sltiu $at, x, 0x30` is `x > 0x2FU`, where `x >= 0x30U` gives `$v0` and an extra nop (`SOUND_FindFreeSPUChannel`, `Player::GetAbility`).
- An assert message spells the compare the source used: `"i_distLinearPercent <= 100"` is `nPercent <= 100`, and `< 0x65` puts the result in `$v1` instead of `$at` (`PSound::SetDistLinearPercent`). A max clamp `(1.0f > f) ? 1.0f : f` gives `c.le.s`/`bc1t` where `(f < 1.0f) ? ...` gives `c.lt.s`/`bc1f` (`Bridge::LeanOnSides`).
- A byte flag tested as `sltu v1,$zero,x; xori v1,1; beqz v1` in a branchy body is `if ((x != 0) ^ 1)`; `!x` compiles to `bnez` (`ZinShellExplosion::Execute`).
- A bool argument built as `a1 = 0; movz a1, one, p` is `f(p ? false : true)`; `!p` and `p == 0` give `sltu`/`movn` (`Player::SetFlyingShield`).
- An address-taken local sitting 8 bytes lower than ours (`sw $zero,0x20($sp)` vs `0x28`) is 16-byte aligned: `T *p __attribute__((aligned(16)));` (`PGfxEngine::SetTexture`).
- `bgez x` with `sra v,x,N` in its delay slot, then `addiu x,2^N-1; sra` is signed division `x / 2^N`; a hand-written `x < 0 ? (x + 2^N-1) >> N : x >> N` gets other registers (`PZBufferFog::Render`: `nX / 0x2000`, `SCREEN_WIDTH / 64`).
- A float stored as a byte through `c.le.s` against 2^31, `sub.s`, `or 0x80000000`, `sb` is `(unsigned char)(unsigned int)f` (`PZBufferFog::Render`). A float passed straight to a `char` parameter converts with no `dsll32/dsra32` sign extension; an explicit `(char)(int)f` adds one (`Interface::DisplayFadeRectangle`).
- `sll v1,x,13; dsll32/dsra32 v0,x,13` before the `bgez` division sequence is `short n = (x * 0x2000) / 0x2000;` (`PZBufferFog::Init`).
- A byte store whose constant is materialized as `addiu t,zero,0x80` (not `-0x80`) writes an `unsigned char` member; retype the member in the header rather than casting at the store, because the cast changes the loop's addressing (`PZBufferFog::m_unk1350`).
- A callee whose callers mask its result with `& 0xFF` returns `bool`; a caller accumulating it with `daddiu s0,zero,1` then `and; andi 0xFF` is `bool bAll = true; ... bAll &= p->Hide(); return bAll;` in a function that itself returns `bool` (an `int` return adds `andi` at the end). Loops over a member array whose assert names it (`"m_pItems[iItem]->IsValid()"`) index the member, `m_pItems[iItem]`, rather than a byte-offset slot pointer (`Peddler::HideItems`, `ExitPeddlerView`).
