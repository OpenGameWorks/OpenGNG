# CodeWarrior idioms: Registers, ordering and inline helpers

Source choices that set register allocation, instruction order and argument setup, including the inline helpers the original used. Each entry pairs an asm pattern seen in the original with the source that produces it, and names the function that proved it.

- A null test repeated inside an already-null-checked block (`beqz s0, end; lui a0,..; beqz s0, skip; addiu a0,..`) is an inline helper's own check: `T *pMgr = ...; if (p != 0 && pMgr->IsValid(p))` inside `if (p != 0)`, with the helper's pointer computed before the test.
- An `addu` whose operand order alone differs, while the loads already match, can turn on a cast: `PR_INT(0x194) = PR_INT(0x190) + (int)arg0->m_nCount;` matched where both the uncast and the swapped forms missed (`PParticleRain::Create`). Try the flip with and without a cast on each operand.
- A repeated expression such as an entity position (`p->m_unk3C ? p->m_unk3C + 0x80 : p + 0x190`) is an inlined accessor; give each repetition its own `{ ... }` block with fresh locals. Reusing one set of function-scope locals swaps their registers; RainTrigger and FogTrigger Execute matched once the second copy was block-scoped.
- Four `lwc1` into f3, f2, f1, f0 followed by four `swc1` is a POD struct copy: `PVec3 v = *(PVec3 *)&m_unk1C0;`. Member-by-member assignments interleave each load with its store. CamSphere and CamCylinder Execute matched this way.
- Store order and local declaration order set instruction order; separate early returns or a duplicated tail replace a shared exit.
- `% 2` versus `& 1`, signed versus unsigned locals, and `for` versus `while` change branch form and shifts.
- `bne a1, v1` against our `bne v1, a1` is the operand order of the comparison: `arg0 == p->m` versus `p->m == arg0`.
- A function the original binds `STB_LOCAL` (column 5 of `config/symbols.tsv`) is `static` in its file and declared in no header: MWCC tracks which registers a static callee defined earlier in the file clobbers and keeps argument registers live across its call (`GsDumpFrameBuffersAsBmp` reuses `a2 = 3` after the static `FudgeBytesToBMPFormat`). A non-static definition reloads them.
- A callee's arity comes from its mangled name and the original's argument setup, not from a neighbouring file's declaration: `ApparitionIsValid__15EntityBaseClassFUi` is static and takes one `unsigned int` in `a0` (`Shield.cpp`). An extra argument adds an `a1` setup and shifts registers.
- The same holds for two variables: `sltu $at, end, x; bnez $at` is `x <= end`, while `end >= x` puts the result in `$v0` (`MemoryManager::Delete`). A parameter the original masks in its own register (`daddu s2,a1` then `dsll32 s2,s2,4`) is reassigned, `pMem = (void *)((unsigned int)pMem & 0x0FFFFFFF);`, not copied into a new local.
- A value computed into `t0`..`t3` before a `sprintf`/`printf` call is a variadic argument past `a3`: count the format's `%` specifiers and pass one argument for each. A draft that drops one keeps the value in another register (`MemoryPool::Allocate`: the pool maximum `m_unk100 << 4` for the third `%d`). `src/scratch/fmtscan.py` lists DRAFT calls whose specifiers and arguments disagree.
- A displacement that differs in a load while the registers agree (`lw a2,0x51A4(t0)` against `lw a2,0x4(t0)`) means the draft reads the wrong member: fix the address, then retune the order (`EntityManager::ValidateDependencyList`). A function name declared without `extern "C"` that is already mangled (`void *__nwa__FUi(unsigned int)`) gets mangled again and its `jal` relocates to a missing symbol.
- `x *= -1.0f` gives `mul.s x,x,c`; `x = x * -1.0f` gives `mul.s x,c,x`. In a `for` header with two induction variables, the order of the increments sets the order of the `addiu`s (`off += 4, i++`).
- When a call's argument loads come in a different order or through the incoming `a0` instead of the saved `this` register, write that member argument as `*(unsigned int *)((char *)this + 0x328)` (`Player::OpenChestMove`, `Player::UnlockGateMove`, `Peddler::ActivateAttackingEnemies`).
- The same raw read on the later argument fixes two member arguments loaded in reverse order (`lw a2,4(s0)` before `lw a0,0x3C(s0)` where the original loads `a0` first): `p->F(..., *(unsigned int *)((char *)this + 4))` (`EntityBaseClass::AddToBGAnimList`, `EntityBaseClass::CreateFireDamageFx`).
- A signedness cast on one argument (`(unsigned int)m_nCount` passed to an `int` parameter) also moves its load: try a raw read or a cast on each argument of the swapped pair in turn. `PParticleFog::Render` needed a raw `unsigned long` read for one call and an `(unsigned int)` cast for the next; `EnemyGenerator::Execute` a raw read of the later argument of both `CreateTimer` calls.
- An address summed as `base + K + i` that the original adds base-first (`addiu v1,base,K; addu v1,v1,i`) while ours folds `K` into `i` first is integer arithmetic on the pointer: `*(char *)((unsigned int)pMgr + 0x59A0 + i) = c;` (`EntityBaseClass::WriteApparitionData`).
- A strided update that the original increments after the loop counter (`addiu i,1` before `andi bit,0xFFFF`) sits in the `for` header behind `i++`: `for (i = 0; i < 16; i++, bit += bit)` (`Pad::RemapButton`).
- A member function whose body never reads `a0` and whose callers leave `a0` unset is a `static` member (mangling is the same); declare it `static` in the class instead of calling an `extern "C"` alias without `this` (`PIOPFile::FrameMaintenacePartA`, `FileSys`).
- `mul.s` with the constant operand first in ours but second in the original takes a hoisted local: `float fK = -1.0f;` declared before the stores (`PMat4::MakeProjectionMatrix`).
- `addu v1,s1(this),s0(off)` operand order follows a real member array: `m_unk208C[i] = p` instead of `*(T **)((char *)this + off + 0x208C)`; split a header `_pad` into the typed array (`PParticleManager::InitGroundDustFx`).
- An integer-typed pointer parameter changes argument scheduling: a SIF address passed as `(unsigned int)buf` to a `unsigned int` parameter (`FlushIOPCommand`).
- A base `addiu $a0,$v1,0x10` followed by accesses at `0x10($a0)` and `0x18($a0)` is a local pointer to a member array: `float (*pBox)[4] = p->m_box; pBox[1][0] ...; pBox[1][2] ...` (`PMeshNode::AdjustPickup`). Direct `p->m_box[1][0]` folds the offset and reloads `p`.
- Float call arguments loaded in reverse order (`f13` before `f12`, one temp register reused) come from named locals: `float fFar = 150.0f; float fNear = 50.0f; Rand(fNear, fFar)` (`AmbientEntity::Execute`).
- Reading a member through a raw cast such as `((float *)pCam)[2]` can swap FP registers where the declared member (`pCam->m_unk00[2]`) does not. Use the class's real members.
- A member pointer read back from the member after it was stored (`sw v0,0x270(s3); lw a0,0x270(s3)`) and then used for the field accesses is `m_x = f(); p = (T *)m_x; p->a = ...; p->b |= 8;`. Keeping the call result in the local and storing it to the member gives the stores through `v0` (`ClockworkStalker::OnHitEvent`).
- A float converted into `f1` and stored second while the first store's value is converted later comes from a float local: `float fH = (float)(H / 2); m[0] = (float)(W / 2); m[1] = fH;` (`PShadowBuffer::SetZBufferRange`).
- A global address built at runtime (`lui/ori` offset added to the `%hi/%lo` symbol into a saved register) next to a call that takes the folded `lui/addiu` constant is two expressions: `cam = (char *)((int)&gEng + 0x19760); f((char *)&gEng + 0x19760);` (`EntityBaseClass::WantsToWake`, `CheckSleep`).
- GS register data/address pairs built on the stack for `SetGsRegisters`, whose original swaps `v0`/`v1` (value loaded before the entry pointer, `&a[2]` in a lower saved register than `&a[1]`), are written through a file-local inline: `inline void SetGsRegPair(void *pEntry, long long data, long long reg) { ((long long *)pEntry)[0] = data; ((long long *)pEntry)[1] = reg; }`, so the first pair is plain stores and the later pairs are `SetGsRegPair(&a[2], 0x18, 0x1B);` (`PParticleManager::UpdateHeatHazeBuffer`, `PFlashScreen::Render`). The inline goes above the function's tag line.
- A select laid out as `beqz a → L; lw default (delay slot); b M; nop; L: daddu a,default` is a call through an inline function `inline int Pick(int a, int b) { if (a != 0) { return a; } return b; }`; the same `if`, `?:` or `if (!a)` written in place gives a `bnez` with no `b` (`PParticleManager::InitHeatHazeBuffer`). Register choices that stay swapped (`v0`/`v1`) under every spelling are a sign of an inline helper in the original.
- Bounds-checked element reads that each reload the count (`lw v0,8(v1); sltu; beqz` per read, the else arm reached by `b`) are separate inline accessors taking the container pointer: `inline int GetSize(T *p, unsigned int i) { if (i < p->m_nCount) { return p->m_aEntry[i].nSize; } return 0; }`, called as `GetSize((T *)m_p, i)`. Caching `p` in a local or writing `i < n ? a[i] : 0` in place CSEs the count (`PStaticInstanceGroup::Render`).
- A clamp or update whose value lands in the wrong register (ours t2, original v1) while every spelling of the test leaves the swap is a fresh local that copies the value first: `signed char nC = nVal; if (nC > 100) nC = 100; nSum += nC;` (MemoryCard::UpdateHeader). The copy is what an inlined helper's parameter produces, so try it before writing the helper.
- An empty function is `jr ra; nop`; a getter is `jr ra; lw v0,off(a0)`.
- MW inlines builtin `abs()`; where the original calls libc `abs` (`jal 0x122520`), a block-scope `int abs(int);` declaration inside the function keeps the call.
- A void callee declaration where the original reads v0 (or the reverse) shifts registers: callee return types follow their own asm.
